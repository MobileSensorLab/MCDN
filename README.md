Mask Conditioned Damage Net (MCDN) is a **~33.5M** parameter unitemporal structural damage classifier designed to process post-disaster orthorectified imagery
generated by first-responder sUAS.
Unlike conventional bitemporal approaches, which rely on comparing pre- and post-disaster imagery, MCDN instead uses *a priori* building footprints as a 4th-
channel soft attention mask, achieving state-of-the-art ordinal regression on the **[CRASAR-U-DROIDs](https://huggingface.co/datasets/CRASAR/CRASAR-U-DROIDs)** dataset.

## Headline Performance

Ten-seed ensemble (argmax decoding) on the four-class Joint Damage Scale, evaluated under three increasingly out-of-distribution holdout protocols:

<img src="data/readme/confusion_triptych.svg" alt="Confusion matrices" width="774">

| Holdout | Protocol | Macro-Precision | Macro-Recall | Macro-F1 | QWK |
|---|---|:---:|:---:|:---:|:---:|
| Spatial Block East | In-distribution | 0.8025 | 0.8168 | **0.8037** | **0.8772** |
| Hurricane Michael | Proximate-OOD LOEO | 0.7876 | 0.8029 | **0.7834** | **0.8640** |
| Mayfield Tornado | Distant-OOD LOEO | 0.7592 | 0.7797 | **0.7623** | **0.8604** |

For context, damage assessment scores on the famous **[xVew2 dataset](https://xview2.org/dataset)** report **Macro-F1 in the 0.65–0.78** range across published architectures.
Direct numerical comparison is complicated by imagery resolution (5 cm sUAS versus ~30 cm satellite) task formulation (unitemporal versus bitemporal), and scoring
conventions (arithmetic Macro-F1 here versus the xView2 harmonic-mean F1 convention).

## Installation

### Training Requirements

- **High-Performance GPU**: A CUDA-capable GPU with support for **[Automatic Mixed Precision (AMP)](https://docs.pytorch.org/docs/stable/amp.html)** operations and **+24GB of VRAM**, such as an NVIDIA
RTX 3090/4090/5090 or equivalent. MCDN may still be trained on less robust GPUs but will require **[configuration](config/config.yaml)** adjustments.
- **uv**: You must have **[uv](https://github.com/astral-sh/uv)**  installed.
  - **Windows**: `powershell -c "irm https://astral.sh/uv/install.ps1 | iex"`
  - **macOS/Linux**: `curl -LsSf https://astral.sh/uv/install.sh | sh`
  - Or via pip: `pip install uv`

### Software Setup

1.  **Clone the repository**: 
    ```bash
    git clone git@github.com:MobileSensorLab/mcdn.git
    cd mcdn
    ```

2.  **Initialize the environment:** Run the following command to sync the project dependencies and set up the virtual environment 
  (this will automatically install the required Python version and packages): 

    ```bash
    uv sync
    ```

3.  **Activate the environment:**
    To use the environment in your shell:
    - **Windows**: `.venv\Scripts\activate`
    - **macOS/Linux**: `source .venv/bin/activate`

### Data Setup

This project relies on the **[CRASAR-U-DROIDs](https://huggingface.co/datasets/CRASAR/CRASAR-U-DROIDs)** dataset.

1.  **Download the Dataset**:
    Go to the **[CRASAR-U-DROIDs Hugging Face repository](https://huggingface.co/datasets/CRASAR/CRASAR-U-DROIDs)** and download the dataset. This dataset is ~200GB; expect your download to take a while.

2.  **Organize the Data**:
    Copy the downloaded contents into the `data/` directory at the root of this repository, *ensuring that the pre-existing **[data/readme](data/readme)** folder is not overwritten. 
    Your directory structure should look like this:
    ```text
    mcdn/
    ├── data/
    │   ├── readme/ # Training images and labels from CRASAR-U-DROIDs
    │   ├── test/   # Testing images and labels from CRASAR-U-DROIDs
    │   └── test/   # Testing images and labels from CRASAR-U-DROIDs
    ├── src/
    ├── pyproject.toml
    ├── README.md
    └── ...
    ```

## Usage

### Train a ten-seed pool

The four ablation presets — `baseline`, `mask`, `typology`, `resolution` — live under `config/presets/`. To launch the full ten-seed pool against a single holdout split:

```bash
python train.py \
    --ablation-preset baseline \
    --fixed-seeds \
    --holdout-event Spatial_Block_East
```

`--fixed-seeds` runs the 10-seed protocol (0, 11, 22, 33, 44, 55, 66, 77, 88, 99). Outputs land under `outputs/ablation/<preset>/<holdout>/seed_<NN>/` (best-checkpoint weights, training log, per-seed metrics, resolved config). Use `--seeds N [N ...]` instead of `--fixed-seeds` to run a custom seed list, or `--config <path>` to bypass the preset machinery entirely.

### Generate ensemble probabilities and ensemble metrics

Once all seeds in a pool finish, run:

```bash
python -m src.postproc.ensemble \
    --variant-roots outputs/ablation/baseline \
    --split Spatial_Block_East \
    --prob-cache outputs/ablation/baseline/Spatial_Block_East/ensemble_probs.pt \
    --output-json outputs/ablation/baseline/Spatial_Block_East/ensemble_metrics.json
```

This caches the per-chip 8-view-D4-TTA softmax stacks to `ensemble_probs.pt` and writes `ensemble_metrics.json` with argmax / EV / hybrid scores under each prediction rule.

### Reproduce the full ablation matrix

The four ablation arms × three holdout splits compose to 110 runs in total (the resolution arm has no Mayfield coverage and only requires 20 runs). 
Expect roughly five days of wall-clock time on a single RTX 5090. Published per-arm and per-split data are provided under `outputs/ablation/<arm>/<split>/aggregate_metrics.json`.
